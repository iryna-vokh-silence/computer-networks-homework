## Завдання 1. Дослідження мережі

### Команди

```bash
route -n get default            # який інтерфейс використовується за замовчуванням
networksetup -listallhardwareports
ifconfig en1
```

### Результат (скорочено до активного інтерфейсу)

```text
=== Interface: en1

Hardware Port: Wi-Fi
Device: en1
Ethernet Address: 1c:1d:d3:ea:4a:c4

en1: flags=8863<UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500
        options=6460<TSO4,TSO6,CHANNEL_IO,PARTIAL_CSUM,ZEROINVERT_CSUM>
        ether 1c:1d:d3:ea:4a:c4
        inet6 fe80::26:f309:4191:4da8%en1 prefixlen 64 secured scopeid 0x11
        inet6 fd36:beca:1978:433d:18b1:9539:c95e:1828 prefixlen 64 autoconf secured
        inet 192.168.88.22 netmask 0xffffff00 broadcast 192.168.88.255
        nd6 options=201<PERFORMNUD,DAD>
        media: autoselect
        status: active
```

Інші інтерфейси (`en0` Ethernet, `en2`–`en5` Thunderbolt, `en6`–`en9` Ethernet-адаптери, `bridge0`) зараз не мають IP-адреси і не використовуються для виходу в мережу.

### Аналіз

| Параметр | Значення | Рівень OSI / пояснення |
| --- | --- | --- |
| **Інтерфейс** | `en1` | Мережевий інтерфейс, через який іде трафік за замовчуванням. Статус `active`, прапорці `UP, RUNNING`. |
| **Тип підключення** | Wi-Fi (бездротове, IEEE 802.11) | Фізичний (L1) і канальний (L2) рівні. |
| **MAC-адреса** | `1c:1d:d3:ea:4a:c4` | **L2, канальний рівень.** Апаратна адреса мережевої карти, за нею кадри доставляються в межах локальної мережі. |
| **IP-адреса (IPv4)** | `192.168.88.22` | **L3, мережевий рівень.** Логічна адреса пристрою в мережі. Це приватна адреса з діапазону 192.168.0.0/16 (RFC 1918). |
| **Маска** | `0xffffff00` = `255.255.255.0` = `/24` | **L3, мережевий рівень.** Показує, що перші 24 біти — адреса мережі (`192.168.88`), останні 8 біт — адреса хоста. |
| **Адреса мережі** | `192.168.88.0/24` | Перша адреса підмережі, хосту не призначається. |
| **Gateway (шлюз)** | `192.168.88.1` | Домашній роутер. Видно в маршруті `default` (завдання 2) і в DHCP-відповіді (`router: 192.168.88.1`). |
| **Broadcast** | `192.168.88.255` | Остання адреса підмережі. Пакет на неї отримують усі пристрої мережі. |
| **Hosts** | 254 адреси: `192.168.88.1` – `192.168.88.254` | Для /24: 2⁸ − 2 = 256 − 2 = 254 (мінус адреса мережі й broadcast). |

Додатково на інтерфейсі є дві IPv6-адреси (L3):

- `fe80::…` — link-local адреса, діє лише в межах локального сегмента;
- `fd36:…` — унікальна локальна адреса (ULA), призначена автоматично (`autoconf`).

`mtu 1500` — максимальний розмір кадру Ethernet/Wi-Fi без фрагментації.

### Команди

netstat -rn -f inet     # аналог ip r

### Аналіз маршрутів

| Маршрут | Що означає |
| --- | --- |
| `default → 192.168.88.1` через `en1` | Маршрут за замовчуванням. Весь трафік до адрес поза локальною мережею (тобто в інтернет) іде на роутер `192.168.88.1`. Прапорець `G` = gateway. |
| `192.168.88` (`/24`) → `link#17` | Пряме підключення: усі адреси `192.168.88.0/24` доступні напряму через Wi-Fi, без шлюзу. В Linux це був би рядок `192.168.88.0/24 dev … proto kernel scope link`. |
| `127` / `127.0.0.1` → `lo0` | Loopback — «сам на себе», трафік не виходить з комп'ютера. |
| `169.254` → `en1` | Link-local діапазон (APIPA). Використовується, коли DHCP недоступний. |
| `192.168.88.1`, `.10`, `.11`, `.12` з MAC-адресами | Записи ARP-кешу (прапорці `L` = link-layer, `W` = cloned). Це сусідні пристрої в мережі, для яких уже відома відповідність IP ↔ MAC. Перший з них — роутер. MAC-адреси роутера та сусідніх пристроїв частково приховано (`xx`) з міркувань приватності. |

### Протокол, через який отримано IP

**DHCP.** Вивід `ipconfig getpacket en1` — це відповідь DHCP-сервера:

- `dhcp_message_type: ACK` — сервер підтвердив видачу адреси;
- `yiaddr = 192.168.88.22` — адреса, яку отримав мій комп'ютер;
- `server_identifier: 192.168.88.1` — DHCP-сервером є домашній роутер;
- разом з IP роутер видав маску `255.255.255.0`, шлюз `192.168.88.1` і DNS-сервер `192.168.88.1`;
- `lease_time: 0x708` = 1800 секунд = **30 хвилин** оренди адреси, після чого комп'ютер її продовжує.

У Linux команда `ip r` показала б це як `default via 192.168.88.1 dev wlan0 proto dhcp`. Слово `proto dhcp` і є відповіддю на питання про протокол.

## Завдання 3. Знаходження публічної IP-адреси

### Команда

```bash
curl ifconfig.io
```

### Результат

```text
31.128.xxx.xxx
```

> Останні два октети публічної адреси приховано з міркувань приватності, бо репозиторій публічний. Повну адресу можу показати викладачу на запит.

### Порівняння локальної та публічної адреси

| | Адреса | Тип |
| --- | --- | --- |
| Локальна | `192.168.88.22` | приватна (RFC 1918), діє лише в домашній мережі |
| Публічна | `31.128.xxx.xxx` | публічна, видна серверам в інтернеті |

**Вони однакові?** Ні, адреси різні.

**Чому?** Мій комп'ютер підключений до інтернету не напряму, а через домашній роутер. Роутер роздає пристроям у квартирі приватні адреси з мережі `192.168.88.0/24`, які не маршрутизуються в інтернеті. Коли я звертаюся до зовнішнього сервера (наприклад, `ifconfig.io`), роутер виконує **NAT** (Network Address Translation): підміняє мою приватну адресу у вихідних пакетах на свою публічну адресу `31.128.xxx.xxx`, яку йому видав провайдер, і запам'ятовує, кому повернути відповідь. Тому сервер бачить не мою локальну адресу, а публічну адресу роутера. Цю ж публічну адресу ділять усі пристрої в моїй домашній мережі (у таблиці маршрутизації видно ще щонайменше три: `.10`, `.11`, `.12`).
